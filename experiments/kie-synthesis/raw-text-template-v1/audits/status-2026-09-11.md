# Carrier-bound template experiment status — 2026-09-11

## Decision

The experiment is stopped before a hardened-v2 live canary. The historical development run did
not meet the quality gate, and the provider then returned `credit_balance_exhausted`. No
transfer-200 extraction, 230-template aggregation, descendant synthesis, or success EDA was run.
Production synthesis code and training publications remain untouched.

## What the earlier 99/100 represented

The structured target-generation artifact completed 100/100 documents. The later 99/100 figure
was a host-audit replay inside the raw-text rewrite pipeline; it was not label-synthesis accuracy.
That raw-text pipeline machine-certified 6/100, and exhaustive manual review accepted only 4/100.
The failure is therefore downstream raw-text ownership and realization, which is the part this
experiment isolates.

## Hardened v2 contract now implemented offline

- Accepted anchors have stable IDs and can be explicitly replaced only when every removed target
  path receives exact, non-overlapping replacement ownership.
- Target and dependency paths must resolve against the pinned label. Derived values declare pure
  derivations and dependency bindings; unknown references and cycles fail closed.
- Target-backed grouping is host-canonicalized. Repeated logical values must have identical
  semantics, and only identical idempotent spans are deduplicated.
- Risk enumeration covers the entire OCR, including accepted-anchor regions. URLs, country values,
  and phone-like numeric tables have targeted regression guards.
- Carrier identity is template-static. Labelled carriers must equal the source label; OCR-only
  resolution requires exact printed signature evidence. Canonical names and aliases cannot be
  hallucinated and all evidence must be owned by carrier-static spans.
- Source bytes, UTF-8 span disjointness, source round trip, page markers, line endings, literal
  regions, sentinel isolation, risk ownership, and a final independent critic pass are host gates.
- Failed documents publish no catalog template. Every phase requires 100% document certification.
  Development and transfer provider launches are pinned off until their preceding gate passes.

## Full-corpus carrier audit and frozen cohorts

All 2,174 pinned source records were classified:

| Carrier-resolution class | Documents |
| --- | ---: |
| source label with accepted OCR anchor | 1,652 |
| source label requiring agent-located OCR evidence | 4 |
| missing label with conservative signature-principal candidate | 33 |
| no defensible carrier identity without external enrichment | 485 |

This makes 1,689/2,174 immediately eligible for a carrier-bound extraction attempt. The remaining
485 cannot truthfully be carrier-bound from the available label/OCR alone; inferring a carrier
from a vessel name alone, agent, location, layout, or generic `AS CARRIER` text is explicitly
forbidden.

The deterministic development selection contains 30 unique documents (18 Bills of Lading and 12
Sea Waybills), including four OCR-only signature-principal candidates. Its preflight validates
153,393 source bytes, 1,088 accepted anchor bindings, and 847 risk candidates; the largest compiler
request is 80,429 bytes. All four candidates and two generic-carrier negative controls were
manually inspected; the candidates have explicit signature context, while the controls correctly
lack a named principal.

The transfer selection contains 200 unique documents with zero development overlap (113 Bills of
Lading and 87 Sea Waybills), including 20 OCR-only candidates. It covers 75 three-or-more-page
documents, 13 dangerous-goods documents, 21 temperature documents, and 84 documents with at least
two containers. Its preflight validates 1,371,440 source bytes, 7,758 accepted anchors, and 8,249
risk candidates; the largest compiler request is 138,391 bytes. This is selection/preflight only,
not 200 completed templates.

## Cost interpretation

Actual experimental spend was $10.887876300000: $0.428874400000 across both canaries plus
$10.459001900000 for development30 v1. Because development30 certified 0/30, its mean
$0.3486333967 per attempted document is a failed-path cost, not a usable steady-state rate.

At that failed v1 rate, a purely arithmetic projection is $80.1856812333 for 230 attempts,
$588.8418069700 for the 1,689 currently eligible records, and $757.9290043533 for all 2,174. These
figures describe why v1 was rejected. There is no actual v2 cost for 230 documents and no
decision-grade v2 full-line projection yet.

The v2 configs pin rates exactly one tenth of v1's rates. Holding v1 token usage artificially
constant would therefore yield $1.0459001900 for 30, $8.0185681233 for 230, and $75.7929004353 for
2,174. This is a rate-only counterfactual, not a forecast: v2 uses a different model and contract,
so actual token counts must be measured after a passing run.

## Required continuation

1. Restore provider credits, then run independent hardened-v2 canaries. Because one prior pass did
   not reproduce, one successful repetition is not enough.
2. Only after stable canaries, enable and run development30. Require 30/30 host certification and
   a manual review spanning complex, repeated, derived, OCR-only-carrier, and ordinary cases.
3. Only after that review, enable transfer200. Require 200/200 certification, inspect a stratified
   sample, and report actual 230-document cost plus confidence intervals and per-mode coverage.
4. Only then implement/run the descendant renderer and synthesis experiments for 30 and 100, with
   deterministic bindings as the default and agent calls only for declared `agent_residual`
   bindings. Success EDA belongs after those gates, not before them.
