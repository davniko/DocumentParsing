## Production flow

1. Load pinned source contracts, current ownership declarations and sampling registries; reject changed inputs or unsupported source scope before paid calls.
2. Rebase proven count/type headers once and compile each source's equipment contract once. Source files are rehashed at stage boundaries, so caching cannot hide an edited input.
3. Choose uniform/mixed mode, feasible number of distinct categories, and weighted canonical pairs. Assign whole equality groups before shipment quantities and loads are checked. There is no mixed-to-uniform fallback.
4. Sample registry-backed goods/packing and validate each actual row against its assigned equipment. Preserve source allocation visibility and package level; do not invent missing public quantities.
5. Generate names, addresses and product wording from plainly separated context. Numeric shipment accounting remains host-owned. Classification wording is context, while the sampled physical form is authoritative.
6. Select a registered alias for each canonical pair and project every per-ID cell, repeated observation and counted summary from its exact row scope. Package aliases and exact count context use their own production projector.
7. Render through ordinary `Campaign`, preserve exact edit proofs, and derive nested handling labels from their final owned printed surfaces. Review the complete rendered OCR and target, not just the changed equipment.
8. Resolve real findings, reject false findings with exact OCR evidence, obtain a fresh hash-bound review after repairs, publish, then generate and independently audit positions.

The same source can produce either mode. With no equipment-inventory policy, the existing default sampling stream remains unchanged. Cold-chain/DG and other equipment-family paths are not silently admitted into this ambient-GP feature.

## Dimension aliases

`40 DRY 9x6` maps to 40-foot high-cube GP; `40 DRY 8x6` maps to 40-foot standard-height GP. The bounded height grammar additionally handles apostrophe/Unicode-quote forms, valid two/three-dimensional forms and corresponding reefer aliases. Width is not mistaken for height. Malformed numeric tails and conflicting explicit code/height combinations are rejected. Bare length follows the agreed standard-height/default-GP policy where that is the actual extraction context.

Twenty new surface aliases were added; the registry now contains 152 aliases across 95 canonical alias records. A 1,719-surface replay found zero changed existing categories; the current published dataset scan found no existing `8x6`/`9x6` occurrence requiring a label correction. These are syntax and future-coverage fixes, not gratuitous relabelling.

The distinction between standard 8′6″ and high-cube 9′6″, and ISO code positions, is cross-checked against [BIC's size/type specification](https://www.bic-code.org/size-type-code/). `42G1` is standard-height 40-foot GP; `45G1` is high-cube 40-foot GP. A semantic review that called `42G1` high-cube was rejected, not propagated into data.

## Configuration

[Ordinary production paired validation configuration](../configs/synthesis/mpci_bl_curated_v7_mixed_inventory_validation.yaml).

```yaml
sampling:
  equipment_inventory:
    source_ids: [EXACT_CERTIFIED_SOURCE_IDS]
    mixed_probability: '0.5'
    category_count_weights: {2: 1}
    # Validation only: force one of each mode per source.
    modes: [uniform, mixed]
```

For a randomized campaign, omit `modes`; `mixed_probability` then governs mixed draws **within the explicitly eligible source scope**, not the whole dataset. Existing `equipment_weights` governs canonical-pair weights; category-count weights govern the number of distinct categories, intersected with source row/equality/capacity feasibility. Impossible requested support fails at startup. These controls do not change how many containers the source retains.

Do not reuse an old configuration's copied capability restrictions or registry digests blindly: use current certified source capabilities and current hashes. This validation's inputs use the R17 working real dataset; completed-run configurations and artifacts are preserved.
