## Product packing detail versus shipment totals

One pre-existing wording guard contradicted the agreed extraction objective:
it rejected `EACH BAG 25 KG NET` as added shipment accounting, while equivalent
`25 KG NET EACH BAG` wording passed. An actual broad-source generated variant
exposed this asymmetry. Per-bag fill and cone capacity are product/packing
details, not by themselves declarations of a shipment net total. A bag also need
not be the declared outer package unit. Their presence alone does not establish
a label omission or arithmetic contradiction.

The overly broad fill/capacity regex was removed from the production wording
validator. Explicit shipment totals and package counts still go through the
existing accounting guards and rendered-text review; meaningful contradictions
remain review findings. This does not authorize inventing or silently accepting
a separate shipment total. Generation prompts, output schemas, frozen configs,
and request identities were unchanged, so completed native generation remains
reusable. No current training row was changed by this validator correction.

Validation: 230 focused tests passed in 8.79 seconds, including ten permitted
packing-detail variants and negative controls combining packing detail with an
unsupported `TOTAL NET` or `TOTAL PACKAGES` declaration. Ruff and diff checks
passed. A seven-repeat, 3,000-call representative validator microbenchmark
improved median latency from 34.205 to 30.926 microseconds; peak traced allocation
remained 4,655 bytes. This is a validator-only measurement, not an API-throughput
claim. Final candidate review and publication gates remain required.

An integrated verification run after this change passed **450 tests in 17.56
seconds**: production campaign/wording behavior, actual native-review provenance,
explicit adjudication application, bounded runner accounting, immutable final
assembly, and independent cohort audit. This is implementation evidence; it does
not substitute for reviewing the campaign's actual generated candidates.
