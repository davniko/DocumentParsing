## Architecture and ownership

The synthesis implementation now has three proved non-training stages:

1. The structured baseline owns formal identifiers, dates, package quantities,
   allocation reconciliation, cargo measures, and transport-capacity validation.
2. The route-first stage owns commercial origin/destination, physical maritime
   endpoints, party geography, place of issue, and freight semantics.
3. The controlled semantic stage owns task-facing package categories, exact equipment
   identities, reefer setpoints, HS identities, country-form cargo origin, and voyage
   identifiers.

The later linguistic/text stage must consume these semantic facts, generate the
remaining party and cargo language, and patch a raw-OCR template. None of the current
stages claims that an unpatched scenario is a training row.

## Route, country, locality, party-geography, and freight generation

The route path is route-first rather than a collection of independent field draws:

1. choose a commercial origin from a configurable mixture of train-isolated observed
   exporter countries and countries with pinned maritime-port support;
2. choose a commercial destination from pinned bilateral WITS trade-flow evidence;
3. resolve physical loading/discharge countries using train-isolated conditional
   evidence;
4. select ports from observed support plus the pinned NGA World Port Index intersected
   with pinned UN/LOCODE;
5. sample populated non-port localities from the pinned GeoNames `cities15000` registry;
6. condition each party role on commercial-origin, commercial-destination, or
   third-country relations learned from the isolated fit split;
7. sample freight arrangement, payment-side relation, and optional payment locality.

Country sampling is alias-free. ISO-3166 supplies identity and one canonical printable
surface. Source aliases are audit evidence only and are never a sampling distribution.

In the accepted 50-document pilot:

- 26 commercial-origin countries were represented;
- 29 commercial-destination countries were represented;
- origin support selected 34 observed-exporter and 16 maritime-registry cases;
- 203 party-locality rows were generated by the route dependency;
- freight was 27 prepaid, 13 collect, and 10 absent, preserving source presence.

The current route contract is direct-route only. The complete 1,157-row corpus contains
18 transshipment-present documents, 13 of them in the isolated fit scope. They remain
excluded because UN/LOCODE and the World Port Index prove that a place is a port, but do
not prove liner-service connectivity between three ports. Inventing a hub mapping or
using distance alone was rejected as insufficient evidence.

## Package semantics and hierarchy

Package categories are sampled from train-isolated role-conditioned support. A bounded
25% exploration arm may choose another category in the same authoritative display-name
family, but only if the token is in the frozen task vocabulary. The application code is
always looked up from the pinned MPCI package registry.

Outer/inner hierarchy is not destroyed:

- task-facing package rows receive generated category semantics;
- metadata-only outer hierarchy rows remain explicit sidecar facts;
- quantities and allocations remain coupled to their original package identities;
- printed surfaces are left for later text realization.

Pilot result:

- 83 package rows across 47 documents;
- 75 generated task-facing categories;
- 8 metadata/untyped rows for which category generation is not applicable;
- 65 empirical-role draws and 10 same-family registry-exploration draws;
- zero package blockers.

## Equipment and reefer generation

Equipment semantics use the pinned BIC/ISO 6346:2022 size/type-code source. Every
four-character generated code is parsed back into size, type family, thermal
capability, and setpoint support. Setpoint-present templates may only receive equipment
that supports a temperature setpoint.

Pilot result:

- 92 equipment rows across 41 documents;
- 71 fit-empirical and 21 registry-exploration draws;
- all 92 codes independently reclassified successfully;
- one source-presence reefer row received a fit-supported Celsius setpoint;
- zero equipment or reefer consistency blockers.

These exact equipment identities are currently a semantic sidecar. The MPCI research
artifact deliberately publishes an empty container-category registry: the platform
accepts a 56,100-member generated code set but has no stable nonlocalized semantic
category for each code. The training task therefore cannot honestly project a container
`typeCategory` until that task contract changes.

## HS and cargo-origin generation

HS sampling separates global identity from customs extension:

- global identity is always a valid six-digit HS subheading in the pinned UK Global
  Tariff snapshot;
- the observed-chapter component preserves broad cargo mix;
- a registry-wide component increases chapter coverage;
- a ten-digit extension is only allowed when the generated customs jurisdiction is GB;
- HS is never used to infer dangerous-goods status.

Pilot result:

- 69 HS values across 25 documents;
- 48 observed-chapter registry draws and 21 registry-wide draws;
- all 69 values independently resolved against the pinned snapshot;
- 30 HS chapters represented.

Cargo origin is treated as a goods-level fact, not automatically as shipper country.
The fit learns same-country versus different-country relationships only from explicit,
ISO-resolvable evidence. A name-only source form may still be replaced safely because
the source string is neither interpreted nor copied. Identifier-bearing origin forms
remain fail-closed.

Fit audit:

- 910 cargo groups, of which 127 have origin data;
- 122 name-only groups are generatable;
- 68 groups are fit-eligible for the relation model;
- 54 same-country and 14 different-country examples;
- 5 identifier-bearing forms remain non-generatable.

Pilot result: 8 generated cargo-origin rows with zero blockers.

## Transport identifiers

Voyage generation is independent of vessel-name generation. It preserves each source
identifier's exact character-class and punctuation shape, rejects normalized collisions
against the complete real corpus, rejects duplicates within the generated batch, and
enforces a configurable minimum normalized edit distance.

Pilot result:

- 44 generated voyage numbers;
- zero source collisions;
- zero batch duplicates;
- one proposal attempt per accepted voyage in v3.

Vessel names are explicitly deferred. The pilot emitted zero vessel names and made no
vessel-name model call.

## Dangerous goods and handling instructions

The dangerous-goods registry boundary is implemented, including:

- atomic tuples for UN number, proper shipping name, primary class/division,
  compatibility group, subsidiary risks, packing group, and technical-name requirement;
- independent shipment flashpoint evidence;
- exact edition/source hashes;
- explicit licence/permission receipts;
- fail-closed production sampling unless the source is maritime-authoritative and permits
  automated processing, compiled artifacts, and synthetic generation.

No qualifying IMDG data source is currently pinned. IMO presents the IMDG Code through
commercial publications/IMO-Vega, while the downloadable UN Model Regulations state
United Nations copyright and are not the maritime IMDG source. The pipeline therefore
correctly did not fabricate regulatory tuples. The accepted pilot encountered two
dangerous-goods documents and blocked both.

Handling instructions are linguistic cargo facts rather than categories. A small
hard-coded phrase registry was rejected. Three handling-instruction documents remain
for the later cargo-conditioned language generator.

## SDV decisions

The full party-structure benchmark used 2,319 rows across 458 templates with three
grouped folds and completed all four candidates on the real dataset.

| Candidate | Mean quality | Raw-valid fraction | Novel fraction | Total fit time |
|---|---:|---:|---:|---:|
| Empirical | 0.9108 | 1.0000 | 0.0000 | 0.002 s |
| Gaussian Copula | 0.7657 | 0.3884 | 0.9504 | 0.788 s |
| CTGAN (GPU) | 0.8470 | 0.7997 | 0.8939 | 97.962 s |
| TVAE (GPU) | 0.8928 | 0.9206 | 0.6705 | 32.035 s |

TVAE is the strongest statistical candidate for party *structure* among the novel
models. CTGAN provides more novelty but loses quality and validity. Neither model is
allowed to generate party names or addresses directly: every direct categorical model
had a source-identity collision fraction of 1.0. Faker/RDT anonymized values avoided
source collisions but were identical across statistical candidates, proving that those
values never reached the statistical model. They are only possible candidate seeds for
a later guarded identity realizer, not final identity output.

For cargo numerics, models remain routed by coherent cargo/profile cohorts. The latest
structured baseline selected Gaussian-Copula variants after grouped quality, stability,
novelty, constraint, and capacity checks. A global neural model is not substituted for
those smaller conditional cohorts merely because the total corpus exceeds 1,000 rows.

## Remaining work before training records can be published

The remaining work is explicit rather than silently filled:

1. Compose the proved structured, route, and controlled-semantic facts for the same
   selected template into one final semantic plan.
2. Generate/anonymize all party identities and contacts, conditioned on the route and
   party role.
3. Generate natural cargo descriptions and auxiliary text consistent with HS,
   package, quantity, weight, reefer, and dangerous-goods facts.
4. Realize printed package/equipment/HS surfaces while preserving each template's local
   formatting conventions.
5. Plan and apply the source-to-synthetic raw-OCR patch, including personal/flavor-data
   anonymization, then prove that every target value is grounded in the patched text and
   no source-sensitive value remains.
6. Obtain and pin a legally usable maritime-authoritative dangerous-goods tuple source,
   or exclude dangerous-goods synthesis from production runs.
7. Add transshipment scenarios only when a pinned connectivity source or another
   evidence-backed route contract is available.

Items 2 through 5 are the intended PydanticAI/linguistic stage. Items 6 and 7 are data
dependencies, not suitable for LLM guessing. Vessel names remain outside the current
scope by explicit decision.
